# 金融计划收费计算系统

Windows单机财务系统，用于客户与账户管理、账单人工复核、逐账户高水位线（HWM）收费、客户季度Invoice、收款更正及完整数据包交接。

当前源码版本为 **0.2.28**。文档修订：**2026-09-10**。本版修复余额导入确认时漏存持仓：页面显示实际将保存的数量，保存较少明细须单独说明原因，后端同时校验并审计。各子账户独立收费，同客户季度合并缴费单。发布及数据保留验证见[项目说明书11.8节](docs/项目说明书.md#holdings-028)；正式数据继续使用用户确认的 `F:\备份`。

## 当前业务与限制

业务链：`基础资料 → 账单复核/余额快照与人工资金流水 → 逐账户季度结算 → 客户Invoice → 收款/更正 → 导出与全量数据包`。

- 每个Sub Account独立计算HWM和Service Fee，按账户舍入到港币分后汇总；同客户同季度的全部Finalized来源可跨Platform、跨收费计划合并为一张Invoice。
- 各账户的HWM收费计划及费率由财务添加、分配（默认20%），文件名编码不作收费依据；Company开票并收款，FC是客户介绍及服务归属人。
- 本地Tesseract OCR与固定`gpt-5.6-sol`辅助识别各自产生候选，人工确认后才能生成余额快照。云端识别由用户主动触发。
- 正式记录通过版本、归档和现金分配台账追踪；首日凭证复验、跳季结算/流水锁定、迟到平台更正已补上回归保护，证据与剩余能力边界见[审查结果](docs/项目说明书.md#gaps)。
- 当前范围是Windows单机稳定使用；Defer、服务器、多用户和通用任意版式OCR不属于已实现能力。

## 开发启动

需要Python 3.12+、Node.js 22.12+及pnpm/corepack。依赖分别由后端锁文件和前端`pnpm-lock.yaml`约束。

```powershell
git clone https://github.com/lch233444/financial-fee-system.git
cd financial-fee-system
./scripts/setup-dev.ps1
./scripts/start-dev.ps1
```

前端开发地址为`http://127.0.0.1:5173`，后端为`http://127.0.0.1:8000/api`。启动前确认端口没有被正式版占用，并使用独立开发数据目录。测试、隔离启动、Windows构建命令见[开发与发布](docs/项目说明书.md#development)；外部二进制准备见[本地构建工具](tools/README.md)。

## 数据与交付边界

正式程序、源码与业务数据分开保存。当前交接登记的正式目录、数据目录和有日期的验证记录见[版本基线](docs/项目说明书.md#state)；路径记录不代表服务此刻正在运行。

服务仅允许loopback。真实客户资料、数据库、附件、识别结果、备份和登录凭据不进入Git。普通开发测试使用隔离合成数据；本地OCR不上传资料，主动运行Sol时图片会发送给OpenAI。日常使用结束直接关闭系统网页；最后一个页面关闭约3秒后后台自动退出，期间新页面连入则继续运行。最小化、切换标签不会触发退出；未提交表单不会自动保存。

每次项目修改同步项目说明书；行为、交付状态或用户确认规则变化同时记录CHANGELOG，具体执行[协作规则](AGENTS.md)。
