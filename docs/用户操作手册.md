# 金融计划收费计算系统 · 用户操作手册

## 1. 启动与数据目录

双击 `FinancialFeeSystem.exe` 或 `启动金融计划收费系统.bat`。首次启动会要求选择数据保存目录；数据库、原始账单、凭证、Excel、PDF及备份统一存放于该目录。系统只监听本机 `127.0.0.1`，不会开放到局域网或互联网。

请不要把数据目录放入公共共享盘。需要迁移电脑时，应从“系统与文件”页面建立备份，再在新电脑恢复。

使用完毕后，请点击左侧栏底部“安全退出系统”，确认后等待“系统已安全退出”提示。该操作会正常停止本程序及其启动的Luna识别子进程，不会删除财务数据；以后不需要在任务管理器中结束进程。仅关闭浏览器标签不会停止后台服务。

## 2. 首次设置

依次建立：

1. Company：填写Company Code、银行/支票信息及默认付款天数。
2. FC：填写姓名及Invoice首字母代码，例如 Tony Wu 使用 `TW`。
3. Platform：填写平台名称与代码。
4. Fee Plan：填写计划名称及Service Fee费率。
5. Client及Sub Account：关联Company、FC、Platform、Fee Plan，并填写开始管理日期与账户号码。

Company、FC、Platform和Fee Plan列表均提供“删除”按钮，仅用于清理刚刚误建且从未投入使用的资料。点击后必须再次确认；如果该资料已被其他基础资料、Client、Sub Account、Settlement、Invoice、编号序列或审计/附件/导出历史引用，系统会显示具体原因并拒绝删除。不要为达到删除目的去改空或绕过历史关联，系统不会级联删除任何客户或财务记录。

## 3. 导入eMPF客人账单

在“账单导入复核”上传 JPG、PNG 或 PDF。系统先分类为账户余额页、供款记录/资产转入记录或未知文件；有文字层的PDF优先在本机直接读取文字，其他文件使用Tesseract OCR。这一步不会把原文件上传到外部服务。供款类及未知文件只能保留为凭证和摘要，不能生成余额快照。

如需提高识别准确率，可启用“ChatGPT Pro辅助识别”。Windows发布包已包含所需的Codex运行程序；首次使用时先到“数据与系统”点击“登录ChatGPT Pro”，在浏览器为本系统专用Luna环境授权本人有权使用的ChatGPT账号。该登录与桌面Codex隔离，退出其中一个不会退出另一个。状态显示READY后，回到“账单导入复核”选中记录并点击“运行Luna辅助识别”。此操作会把当前账单图片发送给 OpenAI，并固定使用 `gpt-5.6-luna` 识别一次。系统不会改用 Terra、Sol 或其他模型再次识别。

系统逐字段比较本地 OCR 和 Luna 结果：

- 两者一致且格式校验通过：预填为待确认值，仍须财务人员确认。
- 任一字段冲突、缺失或格式不合法：标红并直接交由人工选择或修订，不升级模型。
- 内置Codex运行程序缺失或损坏、ChatGPT未登录、登录过期、订阅额度不足、Luna不可用或识别超时：保留本地 OCR，直接转人工复核，不影响其他功能。
- 已确认入账的账单不能再次运行 AI 识别；如需修正，必须按财务更正流程处理。

系统会并排显示原图、识别值、置信度、持仓及警告。财务人员必须逐项核对客户姓名、账户号码、As-of Date及Total Balance；必要时人工修订并选择匹配账户。

- 累计净供款及累计投资盈亏只作参考，绝不会自动写成季度Contribution或Gain/Loss。
- 非季末日期只可保存为余额快照；只有实际退出日经人工确认后，才可标记为Closing候选。
- 关键字段缺失或格式不合法时，系统禁止确认。
- 账户不存在时可建立待确认客户/账户档案。进入“客户与账户”页面，先在“补全待确认Client”补齐Company、FC和Management Start Date并激活Client，再在“补全待确认Sub Account”补齐Platform和Fee Plan并激活账户。

## 4. 余额、流水与凭证

在“资金流水与余额”按Sub Account记录Beginning、Closing余额快照，以及Contribution和Withdrawal。结算开始日发生的资金应包含在Beginning；系统只汇总结算开始日之后至结束日的流水。

每项余额及流水均可上传本地凭证。金额统一以HKD录入。

## 5. 季度结算

选择Client、Platform、Fee Plan、年度及季度后计算。系统以 `Client + Platform + Fee Plan` 建立一个季度Settlement容器，但容器内每个Sub Account使用自己的Starting/Closing Date、Snapshot、流水区间及HWM链独立计算；账户之间不会抵销盈亏或共用HWM。

首次Original HWM由财务录入；以后自动继承上一期Next HWM并记录前序结算。计算结果须复核后Finalize。分母为0时Period Rate显示N/A，并禁止自动Finalize。Finalize后锁定费率、公式版本、账户组成、Company/FC归属及结果；该期间不能再补录流水。更正历史结算必须先处理Invoice，并按时间从后往前依次作废。

## 6. Invoice与Payment

在“Invoice与收款”选择客户季度组合后，系统会按 `Client + Year + Quarter + Fee Plan` 自动纳入该组全部Finalized Settlement；不同Platform只在这里合并，账单逐行显示Platform、Sub Account、账户期间和锁定Service Fee。零收费Settlement也会作为来源保留，但整组Service Fee合计必须大于0才可建立Draft。冻结Company/FC不一致的组合会被拒绝。

Draft建立后若又有同组Settlement Finalize，Issue会拒绝遗漏来源；请先作废Draft，再按最新完整来源重建。同组已有Draft、Issuing或Issued Invoice时，系统不会建立第二张活动季度Invoice。编号在Issue时分配，格式为 `AAA-TW-YYYYMM-NNN`；YYYYMM取客户开始管理月份，NNN按Company+FC持续递增，作废或失败号码均不复用。

正常Issue会在数据库事务外生成并归档中文、英文两份PDF。如异常退出后记录停留在Issuing，界面会显示恢复区：只有两份归档文件均存在时才可“完成签发”；否则选择“退回Draft”，系统清理部分文件后重新出具。两种恢复都保留已消耗编号及审计记录。

Issued后不可修改。无Payment时可Void并填写原因，再重新开票；原编号和归档PDF不会覆盖。当前付款仍可分多次登记，系统显示Unpaid、Partially Paid、Paid或Overdue。二态Payment、付款凭证硬前置、公司承担差额、错误Invoice更正和退款仍未在当前版本实现，处理真实错账前必须按人工财务流程复核，不能用新增虚假收款来对平。

Service Fee为0时只生成结算单，不生成付款Invoice。

## 7. 导出与FC统计

- 单份Excel：Settlement Finalize后，可在计算结果区点击“内部Excel”导出该份Settlement。
- 公司内部财务Excel：在“季度结算”下方按Year、Quarter和Client筛选Finalized Settlement；逐项勾选或点击“选择当前筛选结果”，核对已选数量及Service Fee合计后点击“导出所选内部Excel”。Draft及Void不会进入候选列表。
- Excel严格沿用公司模板的工作表、列序、样式和金额格式。新口径按Sub Account逐行输出各自账户号码、Starting/Closing Date、HWM和Service Fee；Service Fee直接使用系统锁定到分的金额，不由Excel重新舍入。
- 公司模板直接沿用公司原始工作簿，完整保留原工作簿属性、主题、格式、主表第3、4行示例及全部17个原公式；只删除第5行及以下18个个人备注单元格。“Defer 延付利息（待确认）”页的原始数据和36个公式保持不变，但不参与当前系统收费计算。导出时系统会用所选Finalized Settlement逐Sub Account替换主表示例区，并写入对应Excel公式及系统锁定到分的Service Fee。
- PDF：每次可选择中文或英文。正式Invoice PDF在Issue时锁定归档；以后每次下载都会核对归档审计记录和SHA-256。文件缺失、不可读、审计记录缺失或哈希不符时，系统拒绝返回并提示从已验证备份恢复，不会重生成覆盖。
- FC统计：在“经营概览”选择Year和Quarter；只显示当前管理客户数、期间产生收费的不同客户数及这些Finalized Settlement的Service Fee。Company收到的Payment、已收和未收金额不属于FC服务统计。

## 8. 备份与恢复

在“系统与文件”建立备份。备份包含数据库、原始账单、附件和导出文件，并记录文件哈希。恢复会替换当前数据，因此系统先安排恢复，并在下次启动时执行。恢复前请确认备份文件及日期无误。

## 9. 常见警告

- “OCR置信度低于85%”：必须对照原图核对。
- “Luna与本地OCR冲突”：人工选择正确值或手工填写；系统不会升级模型重试。
- “ChatGPT未登录/额度不足/Luna不可用”：继续使用本地OCR并人工复核；不要把错误理解为账单已识别成功。
- “余额日期并非季末”：只保存快照，除非确属退出日。
- “检测到重复”：核对文件哈希、账户号、日期及金额，不能重复入账。
- “Beginning/Closing缺失”：先补齐账户级余额，再计算。
- “Period Rate分母为0”：人工调查数据，系统不会自动出具。
- “同组出现新的Finalized Settlement”：现有Draft来源已不完整，作废Draft并重建；Issued账单则保留原编号/PDF并按后续更正流程处理，不能再开第二张活动季度Invoice。
- “Invoice停留在Issuing”：先核对界面显示的双语归档完整性，再选择完成签发或退回Draft；不要直接修改数据库或复用编号。
- “Invoice PDF归档校验失败”：停止使用该归档，不要尝试重生成覆盖，应从已验证的完整备份恢复。
