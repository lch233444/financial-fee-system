# 金融计划收费计算系统 · 用户操作手册

适用版本：**1.1.0**（已正式交付，验收记录见[项目说明书12.22节](项目说明书.md#meeting-implementation-110)）。文档修订：**2026-09-21**。

本手册涵盖月度账单编号、首次HWM自动填写及修改确认、账单计算与出具、收款情况、客户查询、凭证搜索及期间在管客户总览。完整业务规则、技术依据及验收范围见[项目说明书](项目说明书.md)。本机已于2026-09-21完成1.1.0完整备份、隔离恢复迁移及正式切换，沿用用户确认的`F:\备份`数据目录。

## 1. 启动、数据目录和退出

完整保留`FinancialFeeSystem`运行文件夹，双击其中的`启动金融计划收费系统.bat`或`FinancialFeeSystem.exe`；不能只复制EXE或直接在ZIP内运行。

首次启动选择业务数据目录。程序目录、源码和业务数据分开；本机正式目录登记见[版本基线](项目说明书.md#state)。不要在开发版中选择正式数据目录。若8000端口已占用，应先核实已有程序，不能连续启动多个版本。

本机日常启动使用`F:\财务系统\金融计划收费系统_Windows运行版_1.1.0_20260921\FinancialFeeSystem`内的`启动金融计划收费系统.bat`，然后访问`http://127.0.0.1:8000`。程序已保存数据目录配置；`F:\备份`目前就是正式数据目录，不能当作可删除的临时备份。旧交接登记的`F:\财务系统\财务数据`原样保留，不能与当前目录混用。升级前后完整数据包另存于`F:\财务系统\正式升级备份`。

浏览器地址通常为`http://127.0.0.1:8000`。使用结束直接关闭系统网页标签或浏览器窗口；最后一个系统页面关闭约3秒后，后台及本程序启动的Sol进程自动退出，不再有“安全退出系统”按钮。刷新或3秒内重新打开会保留后台，最小化、切换标签也不会退出；有多个系统页面时须关闭最后一个才退出。关闭前请提交需要保留的表单，未提交内容不会自动保存。

需要重新使用时再次双击启动程序；如果同版本、同数据目录的后台尚在运行，会直接打开原系统。不同版本或不同数据目录占用端口仍会提示核实。不要在程序运行时手工移动数据库、附件或归档文件。

账单导入页选中文件后可查看原件与复核字段；如果浏览器未显示内嵌PDF，点击“打开原件”查看文件。图片直接显示预览。

### 工作台导航与页面使用

左侧分为“工作台、账单制作、收款情况、管理”。账单制作下按客户资料、资金与余额、账单计算、账单出具依次操作；收款情况分组中点击同名入口。页面地址支持刷新和前进/后退，账单详情链接保留同一账单ID。小窗口通过菜单展开导航，Escape收起。经营概览的统计年度和季度筛选居中显示，窄屏上下排列。年度点击展开限高列表，可滚动或输入年份搜索，再点击候选或用方向键和Enter选定；仅输入搜索内容不会改变统计期间，Escape取消并保留原选择。默认选择2026年；展开时选中年份显示在列表中间，上滑选择更早年份，下滑选择更晚年份。2000至2200年连续排列，季度保留全年及Q1至Q4。下方展示所选年季统计；点击“在管客户”数字进入“客户与账户”，年度和季度会自动带入。客户总览已移至该页。

长页面顶部“本页”按钮直接定位相关分区；宽表格在表格内左右滚动，整页保持正常宽度。Tab可进入滚动表格及表单。红色提示显示无法继续的原因；若提示“已保存，但列表刷新失败”，先重新载入核对，不要再次提交。

## 2. 首次设置和完整账户身份

1. 在“基础设置”建立FC、Platform及Fee Plan；Company可在出账单前准备。Company填写全名、内部Code、收款/支票资料及默认付款天数；FC只填写名称等资料，收费计划填写名称和费率；FC缩写和收费计划Code已删除，账单编号保留。
2. 按实际合同在Fee Plan添加HWM利润收费计划及费率，再分配给各子账户；默认20%，可设置不同费率。文件名中的公司编码不决定收费计划，平台上的MPF计划/基金名称也不是本系统收费计划。Defer、固定费用及分档收费当前不使用。
3. 在“客户与账户”建立Client，明确FC及Management Start Date；为每个Sub Account填写Platform、Account Number、Scheme、Fee Plan、开始管理日期和适用的实际结束日期。
4. 确认资料完整并激活。导入时自动建立的DRAFT Client/Sub Account须分别补全后才能进入正式季度结算。

选择账户时始终同时核对 **Client、Platform、Account Number和Scheme**。不同Platform可以出现相同号码，仅看Account Number可能挂错账户。FC是客户介绍和服务归属人，收款主体是Company。

客户选择已合并成一个可搜索框：点击后输入中英文姓名片段，再点击候选，或按↑↓和Enter确认。输入关键词不会更改当前客户；Escape或点到框外保留原选择。没有匹配项时更换关键词；候选很多时继续输入姓名以缩小范围。只输入姓名而未选择候选，不能当作选好客户。

页面默认进入“查询信息”，按客户、年份、季度、FC及收费计划筛选，显示实际受管客户、FC、收费计划和管理期间，不显示客户序号。期间口径与经营概览一致，退出客户只要本季实际受管仍显示。先搜索并明确选客，再查看其账户。“新增客户（自动导入）”提供原件识别、待确认客户与账户补全，以及手工建档和档案维护入口。切换功能页、刷新或关闭页面会丢失未提交内容。

发现同一人重复建成两个客户时，不要删除已入账原件或快照来重建。开发运维可在完整备份后核对并整理尚无结算/Invoice的重复档案，保留原账户、计划、快照及审计；资料冲突或已有结算不能直接整理，详见主说明书6.4节。

误建主资料只在没有后续引用时允许删除。账户有流水、快照或结算等资料时会被拒绝，不能删除上级资料来连带清空业务。

保存基础资料时，按钮会显示“保存中...”。成功后新记录直接出现在列表；若提示“已保存，但列表刷新失败”，先重新载入核对，不要再次提交。若仍出现旧版reset错误，先核对实际启动包和health版本；修改源码不会自动更新正在运行的EXE。

## 3. 导入季度结余与人工确认

### 3.1 上传及本地识别

导入清单支持文件名搜索和待复核/已入账筛选，每页12条。顶部“上传文件、导入记录、财务复核”可快速定位，左右原件/复核区域在小窗口会顺序排列。

进入“客户与账户 → 新增客户（自动导入）”，或“资金与余额 → 导入季度结余 → 原件识别导入”，上传JPG、PNG或PDF，单文件不超过25MB。系统优先读取PDF文字层，其他图像使用本地OCR。本地扫描PDF超过20页时只处理前20页并显示警告，剩余页须人工核对，不能认为整份已识别；Sol超过20页时要求拆分后再处理。本地OCR不把账单上传外部服务。

0.2.29会自动修复本地OCR缓存缺少DLL的情况，首次修复比后续识别稍慢。若安装包本身缺文件，页面会显示具体组件错误并保留原件，不需要连续关闭Windows错误框。升级后，旧记录若尚未确认且没有Sol识别结果，选中原记录点击“重新执行本地OCR”即可重试，无需重复上传。已有Sol结果不能重跑OCR改变比对基线；已确认入账记录也不能重跑，应沿用复核/更正规则。重新识别成功仍须核对客户、账户、日期、币种和结余金额后人工确认；不再提取或复核基金持仓。

系统区分账户余额页、供款/资产转入等非余额凭证和未知文件。累计净供款、累计投资盈亏仅作参考，不是本季度流水或收益。文件完全重复时返回既有记录；语义重复提示需要财务核对。

### 3.2 AI大模型辅助识别

首次使用先在“数据与系统”点击“登录ChatGPT Pro”，在浏览器为本系统专用环境完成本人账号授权。登录与桌面Codex分开，不能复制桌面登录文件。系统显示识别就绪后，在导入记录上点击“运行Sol辅助识别”。

该操作会把当前账单图片发送给OpenAI，固定使用`gpt-5.6-sol`识别一次。它不自动改用第二个模型。未登录、额度不足、组件异常、超时或结构校验失败时保留本地OCR，改由人工复核。

OCR和Sol结果分别显示：一致值也只是候选；冲突、缺失或不确定项必须逐项核对。已经确认入账的记录不能重新识别；已有Sol比对结果后也不能重新运行OCR来改变原比对基线。

确认入账时系统重新校验留存原件。若原件缺失、被替换或路径不安全，会停止入账并保留待复核状态；先核对错误及原始文件，不要修改摘要或绕过校验。

### 3.3 复核和入账

1. 查看原件，核对客户姓名、账户号码、Platform/Scheme、币种、结余日期、结余金额；必要时修订候选值。
2. 先确定“客户归属”：已有客户的新子账户，搜索并明确选择该客户，下面“匹配已有账户”保留为空；已经登记的子账户则选择原账户，系统联动其客户。候选显示客户归属信息，须结合FC、联系方式及账户核对同名档案。已有同名客户但未选择时不能为新账户确认；确为不同的人，先到“客户与账户”建立独立档案再选择。切换原件、修改客户姓名会清空选择；切换客户、修改账户号码或Scheme会清空旧账户。
3. 冲突/不完整项按页面要求逐项人工确认。只有本地分类未知、Sol明确为有效余额页时，才可在查看原件后额外勾选采用文档类型；本地已确定为供款类时不能强行作为余额页入账。
4. 新子账户归入已选客户，只创建待补全的子账户，不再重复建立客户。首次导入且无同名客户时才创建客户及账户草稿。入账后到“客户与账户”为新子账户单独分配收费计划、管理日期并激活；关键字段缺失或格式非法时不能确认。
5. 确认后检查页面显示的Client、Platform、Account Number、Scheme、结余日期和金额及对应原始凭证。

确认仅建立该账户的**历史结余**，并保留原件、识别值、人工值和来源关系。它不会自动登记供款、加款或取款，也不会自动计算或锁定结算。历史持仓数据保留，界面不再展示；新的识别和确认不处理持仓。

补录实际结束日期时仍校验已有结算；日期不能早于已有未作废结算的Closing，也不能使既有结算的日期规则失效。系统不再维护单独的Closing资格标记。

### 3.4 导入错误的撤销

未确认记录可点击删除并再次确认。现存原件及识别结果随记录删除；确认痕迹、重复后继、Snapshot关系或原件异常时拒绝操作。

已确认误入账须填写2至500字符原因并再次确认。只有它与唯一Snapshot来源一致、未被**任何状态**Settlement使用、无附件/导出/后继重复记录引用，且原件完整时才能撤销。成功后删除该次Snapshot、持仓、原件和识别结果，保留审计及Client/Sub Account。即使引用它的Settlement已VOID，也不因此获得删除资格。

删除期间不要并发上传或运行识别。提示“原始文件待清理”时关闭全部系统页面，等后台退出后重启；仍异常则停止并交由开发者检查，不手工删除pending文件。

### 全站账户查看

账户列表默认隐藏：在客户查询、待确认账户、导入匹配、资金与余额、历史结算或Excel预览中，先搜索并点击客户候选，再查看其账户。仅输入名字不会自动选中。清空或切换客户后，旧账户和凭证目标会清除；资金流水更正表单也关闭。客户及账单汇总、跨客户批量导出不受影响。

已建Invoice的账户明细先选择“查看账单账户的客户”，必须与本单客户一致；新建Invoice的客户季度组合已包含明确客户选择。正式账单及凭证原件仍可按原流程读取。

## 4. 资金与余额

本页有三大块：①供款、加款、取款记录与历史结余；②导入季度结余；③导入供款加款取款。顶部按钮可以直接定位。记录区使用与客户页相同的客户、年份、季度、FC、收费计划筛选，并可继续按平台和账户缩小范围。先明确选客，再查看或录入该客户的账户；切换筛选后重新选择录入账户并核对。

历史结余显示本季数据及适用的期初来源，例如选择第二季度会带出适用的3月31日结余；不会随意以最近一天余额代替期初。点击“查看原始凭证”在弹窗查看原导入账单或手动上传的多张图片，不提供下载按钮。记录区下方可展开结算凭证归档，点击“查看原件”先弹窗预览，旁边提供下载。关闭或按Escape返回；原件缺失会明确提示。

### 4.1 导入季度结余

原件识别导入与客户页共用同一流程，上传JPG、PNG或PDF，核对身份、日期、币种和总额后确认。手动录入则选择账户、日期和结余金额，并至少附一张JPG/PNG图片；可以一次选多张，每张作为独立附件。资料与附件全部验证成功后才保存，不能无凭证先记余额。

Closing Date只允许季末或账户实际退出日，必须选择同一账户、日期完全等于Closing Date的结余。没有“Closing资格”勾选框，其他日期的历史结余仍可保留查阅。

### 4.2 导入供款、加款、取款

选择账户、实际转账到账日、资金类型、正数港币金额，并至少上传一份原始凭证，最后点击“保存记录与凭证”。三种类型都不能无凭证保存。供款为定期月供，加款为额外加供，取款为资金流出。本业务转账当天到账，以当天作为生效日；6月30日计入第二季度。账单累计净供款不能直接作为本期供款。

加款说明必填，至少2字；系统按实际选择自动附上到账日期、户口及金额，完整备注上限500字，不设加款金额门槛。旧版全部流入显示为加款，原金额、已完成结算及历史凭证不变，不补写虚构说明。计算净供款为供款加加款再减取款，其余收费与HWM公式不变。

### 4.3 更正及旧凭证

未进入已锁定结算的资金记录可点击“更正”，修改日期、类型、金额或备注，并填写2至500字符更正原因。可选新的凭证替换当前凭证，原件仍列为旧凭证供追溯；没有选择新附件时继续使用原凭证。更正前后字段、原因和凭证变化都保留审计，更正后重新计算相关草稿。

历史无凭证记录可在对应行点击“补存凭证”，系统直接关联该条记录，无需再选“关联记录”。已锁定资金及原件继续受保护，不能直接更正或删除。普通资金记录删除/冲正和手动结余的完整更正/删除尚未提供。

## 5. 账单计算与核对

1. **先补齐前序季度。** 已有Q1而缺少Q2时，先完成Q2再结算Q3。系统会拒绝跳季；Q2仅保存为Draft仍不能继续Q3，必须先Finalize。
2. 在页面上方“本季账户组合总览”依次选择结算年份、结算季度，搜索并明确选定客户；未选客时不显示账户。逐组核对账户和已锁定数量，点击“建立此组合”，或在下方选择平台及Fee Plan。切换客户或期间会清空旧组合、账户输入和计算结果，须重新选择与核对；重新选回也不恢复旧输入。逐账户核对实际管理起止日期。
3. 每个账户选择同账户且日期等于Closing Date的历史结余，Closing Date必须为季末或实际退出日。首次结算选择系统首次结算的合格Beginning Snapshot，系统自动填写Original HWM，并显示来源日期、编号及余额；管理开始较早也不需补录系统首期之前的快照。确需修改首次金额时，填写修改原因，点击单独确认按钮并核对弹窗；改变来源、日期、金额或原因后须重新确认。后续季度继承上季度Closing及Next HWM，金额不可编辑。
4. 核对实际资金区间：从Beginning Snapshot日期之后起算，包含Closing当日。若Q2期初选择3月31日快照，4月1日流水需要计入；若选择4月1日当日快照，当日资金已在Beginning中，不重复计入。
5. 点击Calculate，逐账户复核Beginning、Closing、Contribution、Withdrawal、HWM、Service Fee及原件，再检查合计。各账户收费独立相加，不能用其他账户亏损抵销。
6. 缺资料或凭证时可保存Draft；核对完整后再Finalize。Period Rate分母为0显示N/A，不能正式锁定。

来源改变后Finalize可能要求重新Calculate；先核实变化，不重复点击试图绕过。Finalize锁定结果并复验实际资金区间内的凭证；首日流水复验遗漏已在0.2.21修复，见下一节。**Calculate/Finalize成功不替代财务对原件的核对。**

更正Finalized Settlement时，先处理活动Invoice；有现金或需保留替代关系的错单从Invoice发起Correction。再从HWM链最晚一期倒序操作“作废Settlement”，填写原因并确认。活动Invoice来源或后续结算依赖未解除时会拒绝。

旧记录保持VOID，按同一分组重新Calculate形成下一版本。版本号、旧ID和替代关系不能手工修改；新版本复核并Finalize后才进入替代Invoice。

## 7. 账单出具与收款情况

### 7.1 建立和签发

“账单出具”负责建立、签发、异常恢复及查看归档；“收款情况”负责查找已经出具的账单、确认付款和查看凭证。两页使用同一账单和台账，点击跨页入口会选中原账单。收款情况不展示未签发草稿，账单出具不直接登记现金。

在“账单出具”选择Client、年度、季度组合，再按客户要求选择“本次账单收款公司”建立Draft。切换组合需重新选择公司；不得沿用上个客户的选择。系统自动纳入该客户本季全部Finalized Settlement，跨Platform及不同Fee Plan合并一张缴费单；核对完整账户、Platform、Scheme、Fee Plan、期间和金额，不能选择性遗漏。预览逐行列出来源计划、锁定费率及账户服务费，总金额只是各账户已舍入费用相加，不用同一个费率重新计算。若出现“账户未纳入”提示，先回季度结算处理；该提示不包含尚未激活、缺管理日期或Closed账户，实际受管账户仍须人工逐个核对。全组冻结FC必须一致，公司不限制来源，总额须大于0；零收费来源也属于完整来源。

客户季度Invoice组合上方可搜索客户名称；下方“Invoice清单”可按客户名称或账单编号筛选已建立记录。切换清单筛选会清空当前Invoice，付款或更正前须重新选定并核对账单。

签发前核对收款公司、客户、出具日期、付款期限、逐行费用及付款资料。编号在签发时生成，例如`202609001`，10月第一张为`202610001`；所有客户及公司共用当月流水，不需人工重置。失败、作废及恢复退回草稿已消耗号码不复用；当月999用尽时系统停止签发，需联系管理员确认后续规则。

客户PDF采用正式商务版式“服務費繳款通知書”，显示账单编号、独立出具日期、服务费总额、客户名称、付款期限、公司信息及已填写的银行/支票付款资料。0.2.26新签发的中英文缴费单在标题下显示与系统一致的编号，核对付款时按该编号对应Invoice；长编号会完整换行。客户与期限分栏，单行服务费栏突出总额，银行名称与户口号码等资料按统一字号分列对齐，转账说明与支票说明分区排列；金额字号适度缩小，页脚仅保留细线。签发前请在“基础设置 → Company”核对公司名称、地址、联系方式、银行名称/户名/账号及支票信息，并在Issue时确认付款期限。银行资料可按“銀行名稱：…”、“收款戶名：…”、“銀行賬號：…”各写一行，PDF会将这些标签和内容分列对齐；其他说明照原文显示。账户、季度及计算明细请使用内部结算文件核对。Issue会保存中英文PDF，以后读取原归档；新版样式不覆盖历史账单，后续收款也不改变原PDF金额。

Draft之后补出新Finalized来源时，按提示Void旧Draft再建立完整单。Issued后出现迟到来源需更正，新增平台或收费计划按第6节的完整来源规则处理。

异常退出留在ISSUING时，使用页面恢复区：只有双语PDF均可读取、有页面且与已有摘要一致时才能“完成签发”；两套新旧归档同时存在也须先人工核对。无法完成时可“退回Draft”。两种处理都保留已消耗编号和审计。PDF缺失或哈希异常交由开发者检查，不能覆盖原归档。

### 7.2 查找账单、收款情况与凭证

1. 在“收款情况”的付款账单清单按账单所属年度/季度、收费计划、客户、实际收款公司、FC查找，可同时输入客户名或编号。
2. 混合计划单只要含所选计划就显示整单。例如20%计划100元、30%计划200元，筛选20%仍显示应付300元。
3. 点击上方“未付款”或“已付款”筛选；账单行“未付款”进入付款确认，“已付款”打开付款凭证弹窗，查看原现金、计入本单现金、公司差额和相关退款/转配记录。
4. 弹窗直接预览图片/PDF，其他格式打开原件；关闭或按Escape返回原按钮。缺失原件会显示错误，不能视作已核验证据。点击已付款不会修改状态。

一次性确认收款：

在“收款情况”选中已出具且未付款的账单，进入付款确认区。切换账单会重置付款日期、金额、方式、备注、差额原因及所选凭证；须按当前账单重新填写并核对。付款日期、现金、公司差额等字段顶部对齐；差额提示保留在输入框下方，填写正差额后显示原因字段：

1. 填写实际收款日期、实际现金金额及非空方式。
2. 公司确认承担小额差额时填写金额和原因；为0时不填原因，差额不是现金收入。
3. 上传完整、未认领的付款凭证。
4. 核对 **实际现金 + 公司承担差额 = Invoice金额** 后提交。

当前不接受部分付款、第二笔付款或重复确认；成功后付款、分配、差额和凭证锁定。业务收款情况只有未付款/已付款，逾期是单独提示。不要用虚构收款补平差额。

### 7.3 错单更正、退款和公司承担差额

所有更正统一点击“更正账单”，在同一表单选择收款公司、是否需要重新核算，并填写原因。未收款且无资金台账时可以同时改公司与重算；已有资金记录则锁定收款公司，只能重新核算。1.0.2已正式交付，验收见项目说明书12.18。

已收款错单点击“更正账单”，填写2至500字符原因，核对影响后点击“确认发起更正”。原Invoice转VOID但保留编号/PDF，原Payment保留；系统冲回现金分配，不删除或新造现金。

按第5节处理原Settlement并建立、Finalize完整替代版本，再建立并Issue同组替代Invoice。OPEN更正中的替代单保持资金空白，不先登记新Payment，也不再次发起Correction。

在更正完成区域选择替代Invoice，对每笔原Payment填写“保留分配”和“退款”。二者等于本轮可处置金额；退款大于0时填写日期、方式、原因及退款凭证。保留现金合计加公司差额必须等于替代Invoice金额。

| 情形 | 应填写的内容 |
|---|---|
| 原收120，正确应收100 | 保留100、退款20并提供退款凭证；不再新增100收款 |
| 原收100，因本公司计算失误更正为应收120 | 保留100、退款0、公司承担差额20，并说明计算失误原因；客户不补款，也不新增20现金 |
| 原单尚未收款 | 完成更正仅建立替代关系，新单保持未付款；不要在该完成步骤填写虚构付款或公司差额 |

金额巨大或不属于已确认的小额处理情形，由负责人另行决定，不能理解为系统自动批准任意减免。

连续更正必须先完成上一轮，再从当时的Issued替代单发起下一轮。下一轮只处理仍留存的现金，已退款金额不再分配。原收款、原编号和每轮退款记录应始终可追踪。

### 7.4 仅更正本张Invoice收款公司

仅限已签发、未收款且没有现金分配或公司差额台账的Invoice。已收款账单按钮停用，接口也会拒绝，不自动退款或转移现金。客户、FC、收费计划及今后的客户归属保持不变。

1. 在“基础设置 → Company”核对新收款公司的名称、地址、银行资料和默认付款天数。
2. 在Invoice清单选择原单，点击“更正账单”，选择另一家公司，保持“需要重新核算费用／结算来源”未勾选，填写原因并点击“确认发起更正”。原单转VOID，原编号和中英文PDF永久保留。
3. 在原单更正区点击“建立或查看替代账单”。核对新公司和原金额，在Draft签发区确认付款期限并签发。新编号使用出具年月的全系统下一流水；付款期限可按此次需要覆盖。
4. 从“Invoice更正清单 → 继续处理”回到原单，选择已签发的替代Invoice，点击“完成更正并锁定”。新单仍未付款，此后才按第7.2节登记实际收款。

整个流程直接复用原Finalized Settlement，不作废或重算结算。处理中同组Settlement不能Void或Finalize；若系统提示来源已不完整，先按财务来源更正流程处理，不能省略迟到平台。替代Draft有误时可填写原因作废后重建。处理中需要调整时，回到原账单的更正区点击“调整本次更正”，选择公司和重算选项，填写本次调整原因；系统保留最初原因及每次修改记录。只有未收款、无任何资金或差额台账、无活动替代账单时才允许调整；有替代账单时先核对并作废。若原结算已经作废或来源变化，不能切成仅改公司，应保留重新核算并完成版本链。更正完成后仍未收款的新单可再次受控更正，每轮旧新关系都会保留。

## 8. 导出与经营概览

内部Excel从已锁定计算记录导出；页面不再提供旧版Settlement PDF按钮。Excel沿用公司唯一母版，按Sub Account显示身份、期间和锁定费用；不要修改母版作为日常操作。客户Invoice PDF与内部结算文件分别使用对应入口。

“经营概览”右侧选择统计年度、季度；在管客户随期间变化，点击数字携带年季跳转客户清单。所选期间内至少一个子账户实际受管才计入，同客户只计一次，无费用或尚未出账单仍计入；只有客户登记、未建子账户的不计入。客户与账户清单显示客户、当前FC、对应账户的收费计划及受管期间。管理起止资料不完整时按页面提示补齐后再核对。

### 8.1 内部Excel多计划导出（0.2.33起）

在“公司内部财务Excel”选择Year、Quarter、Client及收费计划，勾选需要的Finalized记录后导出。切换任一筛选会清空勾选，必须重新选择；全部计划可同时导出20%、30%等不同计划。导出副本主表“收费计算”的Z列仅为计划名称（Name）、AA列为结算时收费费率，V列为系统已锁定服务费；R列为投资回报率。无已出具账单时，公司、编号及出具/到期日留空。0.2.33已正式交付该流程，验收范围见项目说明书12.11节。

## 9. 完整数据包与换机

“数据与系统”优先显示业务数据目录、模板是否就绪和Sol状态。具体数据库、模板路径可展开“查看数据库与模板位置”；顶部按钮定位导出、导入及Sol登录。

### 导出给复核人员

在“数据与系统”选择年度季度并导出完整数据包。这只是复核批次标签，包内始终包含导出时**全部**资料、账单原件、附件、付款/退款凭证及系统生成文件，不只包含该季度。

数据包含敏感客户资料，应通过有权访问的受保护渠道单独交接，不放入Git、程序源码或公开演示文件。

### 接收和恢复

1. 发送方和接收方使用完全相同系统版本；新电脑完整解压运行文件夹并选择数据目录。
2. 接收方如已有资料，先导出可恢复的现状数据包并确认本次整体覆盖。导入不会合并两边资料。
3. 在“数据与系统”导入数据包，阅读覆盖提示并确认。
4. 校验成功后等待系统安全退出，重新启动完成替换；不要并发导入、反复点击或手工处理数据库文件。
5. 重启后由有权人员复核客户/账户、原件、附件、结算、Invoice、收款及退款等是否与发送方导出时一致。

新数据包支持不同盘符和数据目录，系统在暂存副本中重定向路径并复验。旧格式备份不具备同样的跨路径保证，季度交接应从同版本系统重新导出新包。

版本不符、缺文件、哈希异常或恢复失败时停止，保留原资料和错误信息。不要改Manifest、复制单独SQLite文件或删除恢复日志来强行导入。系统专用ChatGPT登录不随业务数据包迁移，新电脑由本人重新授权。

## 10. 常见提示

| 提示/现象 | 处理 |
|---|---|
| 账户或客户未Active、资料不全 | 到“客户与账户”分别补齐并激活，核对管理日期 |
| Closing日期或结余不匹配 | 核对同一账户、结余日期等于Closing Date，并且为季末或实际退出日；不手填金额绕过 |
| Draft过期、来源已变化 | 核实更正内容后重新Calculate，再复核费用 |
| 缺凭证、文件大小或哈希不符 | 核对原件及关联，不把Finalize成功视作全部文件完整的保证 |
| 同组出现新Finalized来源 | Draft作废重建；Issued按更正处理，新增平台须满足第6节来源规则 |
| 替代版本链不完整 | 核对原平台是否全部建立替代版本、新增平台是否同组；不要删除来源或直接改数据库 |
| 现金与公司差额不等于应收 | 核对实际到账及已批准差额，不登记虚假Payment |
| 原始文件待清理/恢复未完成 | 关闭全部系统页面，等后台退出后重启；仍异常则停止，不删pending或journal |
| Sol未就绪或识别失败 | 核对系统专用登录，保留本地OCR并人工复核，不反复调用其他模型 |

本手册随实际页面和业务规则同步维护。发现手册与程序不同，应保留错误信息并依据主说明书区分已知缺口和新问题。

### 1.0新增操作提示

客户与账户页默认进入“查询信息”，先搜索并明确选客；点击“新增客户（自动导入）”进入原件识别、新增客户、账户及待确认资料，两个入口分开。切换清空已选账户及待确认目标，未提交的新增输入仍保留。

资金与余额的新记录与凭证合并提交；历史记录补证从该行操作，关联对象由系统固定。保存前核对客户、账户、日期和金额。
