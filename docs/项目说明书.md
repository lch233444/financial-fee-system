## 2. 目标与业务闭环

系统用于把人工Excel收费流程转成可审计的本地财务工作流：

`基础资料 → eMPF账单复核 → 余额与资金流水 → 季度HWM结算 → Invoice → Payment → FC统计 → Excel/PDF → 备份恢复`

核心优先级依次为财务准确、人工最终确认、可追溯、安全边界和操作效率。当前MVP面向单机Windows使用；多人权限、服务器部署和Defer延付利息不在已实现范围。

## 4. 核心业务规则

### 4.1 数据与结算边界

- Company管理公司级收款资料；FC属于Company；Client属于Company和FC。
- Sub Account关联Client、Platform和Fee Plan。
- Transaction与Balance Snapshot均为Sub Account账户级记录。
- Quarterly Settlement唯一边界为 `Client + Platform + Fee Plan + 年度 + 季度`；不得跨客户、平台或收费计划合并。
- Beginning/Closing保存到账户明细；HWM保存在组合结算级。
- 金额以HKD分整数保存，费率以basis points保存，Decimal最终按 `ROUND_HALF_UP` 到两位。

### 4.2 计算公式

```text
Net Contribution = Contribution - Withdrawal
Gain/Loss = Closing - Beginning - Net Contribution
Period Rate = Gain/Loss / (Beginning + Net Contribution)
Adjusted HWM = Original HWM + Net Contribution
Watermark Difference = Closing - Adjusted HWM
Service Fee = MAX(Watermark Difference, 0) × Fee Rate
Next HWM = MAX(Adjusted HWM, Closing)
Days = Closing Date - Starting Date + 1
```

Starting Date当天资金已包含在Beginning，不再重复计入。首次Original HWM由财务输入；后续继承同组最近一期已Finalize结算。分母为0时禁止Finalize。Finalize后公式版本、费率、账户组成与结果不可原地覆盖。

### 4.3 Invoice与Payment

- 只有Finalized且Service Fee大于0的结算可建立Draft Invoice。
- Invoice在Issue时分配 `CompanyCode-FCCode-ClientStartYYYYMM-NNN`；NNN按Company+FC持续递增，Void号码不复用。
- Issued后锁定；修正需Void并重开。中英文PDF在Issue时归档，之后返回原文件。
- Payment支持多笔，累计不得超过Invoice金额；生命周期与付款状态分离。

## 5. 账单识别与交叉核验

识别流水线如下：

1. 上传文件先做大小、magic bytes、哈希和语义重复检查。
2. 本地OCR始终先运行并独立保存；PDF优先文字层，扫描PDF逐页OCR，长截图重叠分段。
3. 分类为账户余额页、供款记录、供款/资产转入记录或未知文件。
4. 只有用户主动点击时，才通过应用专用ChatGPT登录把当前图片发送给OpenAI，并固定调用 `gpt-5.6-luna` 一次。
5. OCR与Luna按标准字段及基金名称比较；冲突、缺失、单侧值或异常全部进入人工复核。
6. 非余额文件在后端硬性禁止生成Balance Snapshot；AI接口也不能写入Transaction、Settlement、Invoice或Payment。

2026-08-26的5份授权样本中：OCR文档分类5/5，Luna文档分类5/5；3份余额页四个关键字段OCR为12/12、Luna为10/12；两份非余额凭证均正确分流。该结果只代表当前小样本，不能外推为通用准确率。详见 `docs/客户账单OCR_Luna识别评估_20260826.md`。

## 6. 隐私与安全

- 后端只允许 `127.0.0.1`、`localhost` 或 `::1`，并校验Host和本地写请求标记。
- 客户账单、数据库、附件、导出和备份均在用户数据根，不进入Git。
- 不使用或保存OpenAI API Key。Luna使用独立 `CODEX_HOME`，不得继承桌面Codex的AGENTS、插件、Hook、MCP或登录凭据。
- “无需API Key”不代表完全离线；主动使用Luna会把当前账单发送给OpenAI。
- AI结果只作为待确认辅助字段，不能自动入账或升级/切换模型。
- 真实样本测试必须先取得用户对云端上传的明确同意。

## 10. 已知缺口

- 结算API仍可能通过手填Closing绕过“季末或实际退出日”凭证资格。
- Beginning尚未关联明确的 `beginning_snapshot_id`。
- Transaction/Payment附件强制规则、退款/贷项/错误付款撤销尚未完成。
- FC统计目前按Settlement期间归集，不是Payment Date现金发生期；前端缺少期间选择。
- 多数基础资料和业务记录缺少完整编辑、删除或冲正流程。
- Defer延付利息、邮件、用户权限、服务器部署、任意版式OCR和模板版本管理尚未实现。
